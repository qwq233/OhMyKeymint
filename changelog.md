## What's changed

This release migrates OMK and the injector from `rsbinder` to Android's native Binder runtime. Binder objects, Parcels, and private Unix-socket RPC now use the device's Binder libraries, with shared interfaces generated by the official Android SDK Rust AIDL backend. Android 13 or above is now required.

Keystore interception now runs through native Binder callbacks and generated AIDL dispatchers. The ioctl hook redirects validated local receivers and tracks transaction lifetimes, replacing the previous manual Parcel parsing, reply rewriting, and operation-publication machinery. Caller UID, PID, and SELinux identity, transaction flags, interface metadata, and one-way calls follow the native dispatch path, with version-specific handling for older framework layouts and KeyMint parameter decoding.

Live security-level handles now follow the current caller filter and per-method intercept settings, returning to System when interception is disabled or the caller is no longer selected. Existing OMK operations remain bound to the RPC session that created them. RPC connection recovery now runs in the background and publishes the main, auth-token, and lifecycle connections together. Ordinary requests remain on System while connections are unavailable or confirmed stale, and OMK routing resumes after recovery. Calls already dispatched to OMK preserve its business errors and actual Binder failures without synthetic middleware error codes.

Authentication tokens now retain their original System MAC when received and cached. Before an OMK operation uses a token, System KeyMint verifies the MAC and OMK translates it for its own KeyMint. Successful translation is cached per operation for subsequent AAD, update, and finish calls, and translation failures trigger operation cleanup. The existing `force_skip_system_biometric_hat_verification` switch remains the explicit MAC-verification bypass.

System HAT verification now supports KeyMint devices exposed through `android.security.compat`, explicitly requests SHA-256 for HMAC verifier operations, and preserves authentication failures instead of collapsing them into a generic system error. Cached verifier keys are regenerated only when invalid or requiring an upgrade.

Payload fd handoff and remote-call cleanup were tightened, dependencies were updated, and builds now require Android SDK Build Tools 37.0.0 for AIDL generation.
